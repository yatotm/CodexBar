# 用量中心实现与验证

用量中心是独立的采集与查询模块，由 `CodexBarAppDelegate` 装配。原 app-server 账户链路、Hook 历史聚合和 `CodexActivityMonitor` 不读取新数据库，也不把远程快照用于防睡眠或自动重置。

## 数据流

```text
本机日志 ── 本机 Python 采集器 ─┐
远程日志 ── 定时采集 + SSH ───┼─ 协议校验 ─ Mac SQLite ─ 菜单栏 / 用量详情
远程日志 ── Docker + SQLite ──┘                │
                  SSH 只读导出 / HTTPS        └─ 按来源与请求去重查询
```

### 实时任务通道

`ActivityCollector.py` 与历史采集器独立。原生 Hook 写入 `~/.local/state/codexbar-activity/activity-v1.sqlite`，只保存哈希会话标识、工具、项目显示名、状态和时间。内部 PID 与进程启动时间用于检查进程是否仍存在，不传输到 Mac。未知或缺失的生命周期保持未知，不凭静默推断完成。

每次事务提交后写一个固定大小的通知文件。Linux 使用 inotify，macOS 使用 kqueue 阻塞等待；不能直接把 WAL 修改事件当成提交完成，否则可能永久漏读最后一笔事务。空闲时每 60 秒检查进程并发送保活快照。

`Stop`、`SessionEnd` 只结束已有的运行、等待或待确认任务，不为空会话创建任务，也不覆盖已完成记录。待确认任务恢复事件或结束时保留原起点，新一轮提示才重置起点。最近完成与终止统一展示 10 分钟，Mac 使用到期定时器清理，无新事件时也会消失；旧采集器生成的无起点终止记录只在展示层过滤，不迁移或删除历史数据库。

Mac 使用独立 SSH 子进程，保留系统主机校验，不使用用户的 SSH 复用连接。快照包含 schema、epoch、revision，最多 500 个会话和 512 KiB；消费后确认版本。重连重新读取完整当前快照，不需要迁移历史游标，也不补发旧通知。断线保留显示但标记未知，重试采用指数退避和随机抖动。

`SystemConnectionGate` 汇合工作区睡眠通知、IOKit 合盖事件和 `NWPathMonitor`。网络可用仅允许尝试，SSH 是否接通由真实连接判断；合盖门槛优先于 DarkWake 和网络变化。本机 Claude 在断网时仍可读取状态，合盖时暂停。取消管道唤醒阻塞的后台读取，关闭采集进程，不影响用户终端。

来源启用状态独立保存在 `RemoteActivity.enabledSourceIDs`，不改变历史数据库或原 Hook 聚合 schema。源编辑页可以安装或移除本程序的 handler，保留其他配置。远程事件不输入本机 `CodexActivityMonitor`，不参与防睡眠和异常会话保护。

### 采集端

`UsageCollector.py` 只依赖 Python 标准库。SQLite 记录文件位置、前缀指纹和经过筛选的事件，按文件增量读取。未完成的 JSONL 行留到下一轮，单行和每轮读取时间均有上限。

- Codex 新格式优先使用 `token_usage_record` 的请求身份去重；启用该路径后，不再叠加同文件的累计计数事件
- 旧 Codex 格式以会话内累计计数的增量计算，计数回退时保守处理并报告可能少计
- Claude 同一个消息的流式快照按消息身份合并，计数保留完整值
- 不同来源的贡献分别保留，Mac 查询合计时按事件身份去重，选择完整的观察
- 日志没有明确提供的登录方式保留为 `unknown`，来源标签仅作为用户指定的历史归类

所有 SQL 参数通过绑定传递。原始对话、工具参数、工具结果、登录 Token 和完整工作路径不进入导出协议。项目显示名会进入协议。

`Collector/install-timer.py` 安装同一日志用户运行的 systemd oneshot 服务和五分钟定时器。服务使用 `collect --quiet`，独立更新既有数据库；Mac 设置 `collectorCacheDirectory` 后使用 `--skip-scan` 导出。调度方式切换不改协议、数据库格式或去重身份。

定时服务设置 `PrivateNetwork`、只读文件系统、有限运行时间和内存上限。标准输出不进入 journal，既有统计缓存和游标在切换前后保持一致。各平台的 systemd 单元需要通过实际目标版本的 `systemd-analyze verify` 检查。

### 传输与生命周期

菜单栏沿用 `StatusItemController`、原有 popover、悬浮面板和焦点恢复流程。三个标签保存在 ViewModel 的内存状态中，不修改原主面板布局设置。菜单摘要独立查询，详情窗口的筛选不会污染菜单数据。切换标签时关闭原有侧边详情面板。

SSH 只执行固定采集器，主机别名先校验，远端参数使用 shell 单引号转义。保留系统主机密钥校验，禁止密码交互、agent forwarding、自动端口转发和本地配置命令。

HTTP 只提供固定只读路由，使用专用令牌鉴权、固定分页上限和有限并发。Mac 仅接受 HTTPS，沿用系统 TLS 校验，拒绝重定向；令牌存入钥匙串。

Mac 后台任务单轮分页和回填有上限，取消与超时会终止本轮子进程。睡眠时取消采集，自动刷新失败后退避。SQLite 更新来源游标和批次记录时处于同一个事务，失败保留已有缓存。

### 查询与身份边界

每日模型排名、事件计数、峰值、连胜和单轮最大时长直接查询既有记录，不增加持久化列，不改变原 Hook 聚合 schema。原 Hook 可用时保留其悬浮详情，缺少 Hook 时用独立设备日志补充。

本机和 SSH 读取可通过 `--include-auth-type` 获取当前 Codex `auth.json` 中明确的类型字段，输出只有枚举值；它不写数据库，也不回填历史身份。定时器未启用此选项，原凭据文件隔离保持有效。HTTPS 端未提供当前身份时，客户端兼容缺失字段。历史归类按来源保存；周限历史另按每条记录的提供商和认证上下文判断，不能用当前登录状态回填所有历史。

### 官方分析与维护

`UsageAnalyticsClient` 是独立 actor，使用临时 `URLSession` 和本机 Codex OAuth。限定 `https://chatgpt.com`，拒绝重定向，限制超时与响应大小。认证失败只重新读取一次 CLI 登录文件，不自行刷新或改写凭据。请求前后验证账号一致，缓存按账号哈希隔离，目录权限为 `0700`，文件为 `0600`。

当前经过验证的只读接口：

- `/backend-api/wham/usage`：当前主额度窗口和账号核对
- `/backend-api/wham/usage/daily-token-usage-breakdown`：按日模型额度权重，`units=percent`
- `/backend-api/wham/analytics/daily-workspace-usage-counts`：按日未缓存输入、缓存读取和输出总量

日查询固定 UTC、`group_by=day`，请求最近 70 天；每 15 分钟更新。它们是官网内部接口，不是稳定的公开 API。`UsageAnalyticsParser` 集中管理字段和单位校验，拒绝未知单位和不匹配的账号；两个响应日期取并集，缺少 Token 保持缺失。整份成功响应替换缓存，不跨查询累加归一化模型权重。

`UsagePrices.json` 保存独立、带日期和来源链接的官方价格快照。价格更新只修改该文件；解析更新集中在 parser。未知模型不得套用平均价格，日期后缀只在已知模型家族内匹配。订阅 Fast credits 倍率与 API 实际报价不同。当前按脚本口径使用该倍率计算额度折合美元，并在界面明确说明，不宣称为 API 账单。

`UsageModelAllocation` 使用 Quota Compass 的混合单价反推：在同日各模型输入输出结构相同的假设下，以额度权重除以混合单价，归一化后分配各类 Token。整数分配使用最大余数法，保证日总数守恒；未知价格不套用平均单价。模型 Token 与 credits 均明确标为估算。

`UsageAnalyticsValuation` 用实际截止时间划分周期。跨周期边界日按已观察周限增量分配，覆盖不全或无增量依据时退回时长分配，并显示该限制。相邻周期对同一天的分配不会重复计量。外推使用与官方统计读取时间对齐的额度比例，末次观察较早不阻断计算。没有 Token 和模型额度权重的空白日跳过；有权重但缺 Token 的日子，按已计价权重占比匹配额度比例并外推，保留缺失提示。原始缓存结构不变，估算结果只存在内存中。

零用量时五分钟内的截止时间漂移仅在展示层合并，原始窗口仍保留。

额度历史通过独立的 `quota-history` 命令和 `quota-history-v1.sqlite` 采集，旧 `collect` 导出协议、`valuation` 命令及数据库保留。`collect` 完成后在剩余时间预算内更新历史缓存，额度缓存失败不会使原日志统计失败。定时任务只扫描日志，导出阶段才读取当前 Codex 账号摘要。

新缓存复用有界增量读取，按通用 `model_provider` 和 `auth_mode` 识别模式；提供商变化会清除先前身份状态，防止 OAuth 状态泄漏到 API 记录。显式账号标识只保存摘要，查询时过滤其他账号；没有历史账号标识的记录要求用户确认来源归属。扫描与导出均不传输 Token、会话正文或工具参数。

`UsageQuotaHistoryController` 管理本机与 SSH 来源的独立缓存、选择和取消。来源配置与账号参与缓存身份，切换账号或来源时用 generation 丢弃迟到结果。每十五分钟同步，首次或过旧缓存回退到有界扫描；失败保留有效缓存，不影响其他来源。每个远端来源独立保留证据，仅在计算时合并，不写入原官方快照，因此停用来源能立即撤销贡献。HTTPS 历史导出暂未实现。

跨来源合并保留源内回落标记，对各源本身单调时出现的交错旧回执构造单调观察曲线，避免假回落。跨源重复观察不累加百分比。截止抖动超过两秒但不超过一分钟时，仅在观察时段重叠的条件下对齐，非重叠实际重置仍独立。后续实时观察继续复用 app-server 已有响应。

接口维护时先保存脱敏结构说明，补充合成 fixture，验证缺失日、零额度、提前重置、账号切换和未知模型。不要把真实凭据或完整个人响应写入测试仓库。`Tests/UsageAnalyticsLive.swift` 是手动联网诊断，默认测试脚本不运行它。

Apple 对弹窗尺寸动画的说明见 [NSPopover.contentSize](https://developer.apple.com/documentation/appkit/nspopover/contentsize)

周额度参考是独立的账号设置键 `UsageAnalytics.quotaReference.<account-hash>`，默认禁用，可选 Pro 5x 或 Pro 20x。只在没有正数外推结果时补充所选经验范围，界面必须区别 `用量推算` 和 `额度参考`，不改变官方缓存或历史记录。

`UsageAnalytics.planHistory.<account-hash>` 独立保存按周期观察的官方套餐类型与时间戳，最多保留 210 天和 512 个变化点。优先使用新鲜额度响应的 `planType`，其次使用账户字段；`prolite` 映射 5x，`pro` 映射 20x，未知类型不猜测。相同周期且相同档位不重复写入。升级不覆盖旧周期，同周期多档位变化停止混合外推并显示变化文案。官方原值缓存和原数据库结构不变。

### 查询和绘制性能

SQLite 在独立 actor 内一次筛选并去重到临时表，复用它计算日汇总和五种分组。临时表只在连接内存在，不改变持久化 schema。最近查询有界缓存，数据写入、来源变更、外部数据库版本或 UTC 日期变化时失效；SQLite 进度回调响应任务取消。

玻璃纹理使用四张复用的小位图，避免滚动和动画逐帧生成成千上万个噪点路径。本地验证构建启用 Swift 优化，保持 Debug 独立 bundle ID。

托盘通过 `MenuHostingController` 的原生翻转坐标容器承载 SwiftUI。容器禁止子视图自动缩放，设备列表设置完整目标高度并固定于顶部，外层由系统动画改变裁剪区域。托盘关闭 `UsageReveal` 的独立高度动画，避免内层与窗口各自插值导致中间展开。备用面板使用同一容器，保持顶部窗口坐标。

用量中心仍使用 `UsageReveal`，收起时立即隐藏文字。箭头使用固定尺寸符号即时切换。区间摘要的悬浮状态单独管理，固定列宽并使用虚线浅色详情容器。Codex 和 Claude 卡片的身份同时包含展示代次和当前标签，所有标签切换均重新播放额度入场动画。

### Claude 配置

可选接入在独立目录保存包装器和安装记录。状态栏原始输入通过临时文件恢复为标准输入，再用 `exec` 执行原命令，保留输出和退出码。Hook 只写经过筛选的元数据，不产生审批决定。

已有 ccline 额度缓存按白名单读取，单文件上限为 64 KiB。兼容旧 Python 的时间解析会把纳秒截取为微秒；单一 `resets_at` 只归属七天窗口。五小时比例保留，重置时间未知。

安装锁只用于协调本程序实例。写入前再次检查设置文件是否改变，避免覆盖常见并发修改。卸载只恢复自己仍在管理的状态栏与 Hook；状态栏已被修改时停止，不能用备份覆盖新的用户配置。

## 兼容性

该模块不变更既有持久化键、Hook 聚合 schema 或 helper 协议。新数据库与协议的初始版本是 `1`。未来解析含义、去重身份或格式变化必须先评估已收集历史和不同版本的统计端，不可直接清库或给历史缺失字段补出确定值。

原日志可能已被上游清理，因此不能假定将来总能从原日志重建全部保留期。对旧累计格式、复制后改变身份的会话和无法解析的记录，不应宣称能得到无遗漏的账本。

来源选择使用新键 `UsageAnalytics.historySources.<account-hash>`。本机既有选择键继续可用。缓存目录和新命令与旧版本独立，不重写原数据库或官方统计快照。

## 手动验证场景

- 菜单栏点击打开主面板，切换 `全部`、`Codex`、`Claude`，检查热力图悬浮、侧边面板关闭、机器范围和额度缺失状态
- 从主面板和右键菜单打开用量详情，检查窗口焦点、切换桌面、关闭重开和与设置窗口切换；修改详情筛选后再次打开菜单，标签和摘要应保持原范围
- 分别筛选机器、工具、登录方式、模型、项目和时间范围，核对日志中对应的已知请求
- 在 SSH 来源追加新日志，检查增量更新；断开网络、修改主机密钥或使用错误路径，检查保留缓存与明确错误
- 使用同一请求的两个日志副本，检查单机视图与去重合计的区别
- Claude 接入前后检查原状态栏输出，执行任务、等待批准、完成和退出，再卸载并核对原配置
- Claude 未提供额度字段或快照已过重置时间时，应显示未知或等待新快照
- Mac 睡眠时停止采集，唤醒后恢复刷新；这些状态不应触发原有防睡眠或自动重置
- Docker 以只读文件系统和有限资源运行，核对只有日志子目录与数据目录被挂载；验证无令牌拒绝访问、错误分页参数被拒绝
- HTTPS 使用有效证书连通，并确认错误证书和重定向被拒绝，不能为测试关闭验证

本机旧版 Xcode 若缺少上游使用的 SDK API，需要更新开发工具。自动测试通过不能替代完整 App 构建与菜单栏手动验证。

## 周期刷新的睡眠边界

`CodexBarAppDelegate` 统一订阅 `NSWorkspace.willSleepNotification` 与 `didWakeNotification`，同时通知 Codex 状态模型和用量中心。设备同步不再自行维护另一套通知订阅。

`RefreshTaskCoordinator` 支持暂停门禁，禁止暂停期间新任务启动，并通过 generation 丢弃入睡前的旧结果；已经排队但尚未执行的任务也检查门禁。正式唤醒后恢复原用户的自动刷新意图，Codex 状态模型补一次刷新。`AppServerSession` 在写入每一步请求前检查任务取消，避免已取消的刷新继续请求或重试。

官网分析和独立额度历史读取也设置暂停门禁，来源变化或视图重新进入不能在睡眠期间启动新读取。未改动 helper、Hook 实时任务或自动重置状态机。自动重置已授权的专用唤醒操作与普通周期轮询保持独立。

模拟测试覆盖暂停后刷新尝试、排队请求取消、在途结果丢弃和恢复。真实系统验证场景包括合盖休眠、后台唤醒保持暂停、开盖正式唤醒、外接显示器合盖工作模式，以及在请求尚未结束时入睡。

实时展示合并只作用于副本，在模型后附机器名，不改写本机监控快照。断线任务移入任务中心的“状态待确认”，不计为运行或完成。模型优先读取 Hook 字段，再从受限会话目录的有界尾部提取；缺失时显示未知模型。协议的可选 `modelName` 与独立模型表不改变原任务表或历史库。

任务模型、思考深度和机器名分别传递给统一格式化函数，机器名不再拼入模型字段。实时协议可选提供 `eventName`、`toolName` 和 `activeSubagentCount`；附加记录与主任务更新时间一致才生效，旧采集器更新主记录后不会误用遗留阶段。原任务表与 Hook 历史聚合格式保持不变。
