# 设计原则与关键决策

简体中文 | [English](../en/DeveloperGuide/design-decisions.md)

## 状态只有一个所有者

账户、实时任务、历史账本分开。共享 daemon 是 Codex 会话事实来源，采集器负责白名单投影，Mac 负责显示。历史估值不从任务卡片的累计 Token 反推，避免重复计算和认证归属丢失。

本机 `CodexActivityMonitor` 统一输出本机通知与电源依据。`ActivityPresentationModel` 合并展示远端和 Claude，不能顺便接管电源或自动重置。

## 用户意图与临时健康分开

开关、布局和自动刷新偏好是用户意图。来源健康、系统授权、睡眠门禁决定当下是否执行。临时失联不能重写布局、清空账本或等价为任务结束。

| 情况 | 处理 |
| --- | --- |
| 账号读取失败 | 同账号缓存标记 stale，任务独立运行 |
| 实时来源失联 | 显示待确认，暂停本机任务防睡眠和静默保护 |
| Token 基线或历史字段缺失 | 保持未知，不补零 |
| 旧 CLI | 提示升级，历史保留可读 |
| 取消或连接代次变化 | 丢弃旧结果，清理自己的连接与断言 |

## 最少的进程与权限

复用每台机器自己的共享 daemon，不再为 GUI 启动独立 stdio app-server。各机监听器使用 Python 标准库，通过 Unix socket 访问本机后台。远端数据使用已配置 SSH，不开公网端口。

Helper 只处理固定电源操作，沿用现有签名和授权，不增加单独管理 App。不得向 Helper 增加账号、日志、网络或任意命令能力。

## 历史兼容

不复制上游新版本的卸载重建方案。旧 Hook schema、保护身份、用量和价值账本不变；新事件放独立库，按稳定 ID 导入原记录协议。旧 CodexBar handler 在新来源健康后撤除，保留其他应用配置。

不维护两套生产 Codex 实时采集。保留旧解析代码供历史与回归，并不意味着旧 CLI 自动回退到 Hook。

## 资源与副作用

动画只在可见时运行，保留 AppKit 固定顶边的窗口尺寸动画，不引入持续文字闪动。日志排版与历史查询在后台，SQLite 连接和有界查询缓存复用。

通知只消费实时可信转场，恢复快照不重放。自动重置将取消、网络等待、重试预算和消费截止时间统一检查，重入必须等上一次清理完成。系统唤醒只为用户明确开启的电源功能服务。

## 审查依据

每次上游同步按功能意图而非文本冲突适配。发布配置、签名、iCloud、数据库替换和高频动画不能直接覆盖 fork。逐项结果见 [上游更新审查](upstream-adaptation.md)
