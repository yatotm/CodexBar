# 多机器用量中心

点击菜单栏图标，在原有弹窗顶部选择 `全部`、`Codex` 或 `Claude`。`全部` 展示跨设备日志摘要，`Codex` 保留原作者的账户额度、用量热力图和工作流交互，每日详情在 Hook 历史不可用时由设备日志补充，`Claude` 展示启用了 Claude 采集的设备与被动额度记录。

弹窗底部的 `用量详情` 打开详细统计窗口，可按机器、工具、登录方式、模型、项目和日期范围查看，也可以管理 SSH、HTTPS 来源。右键菜单中的 `用量中心` 进入同一窗口。详情筛选不会改变托盘标签。

首次启动只显示菜单栏图标。图标被其他菜单栏项目挤出时，可以再次打开 App，或使用默认快捷键 `⌘⇧W` 调出原有主面板。

## 数据含义

原主面板的 Codex 账户额度继续由本机官方 `codex app-server` 获取。用量中心读取每台机器的会话日志，两个范围不同，累计 Token 不相加。

`全部` 和 `Claude` 的热力图与原 Codex 卡片使用相同布局，展示已采集 Token、单日峰值、当前连胜、最长连胜和最长单轮。累计值只覆盖保留日志，不能称为账号全时累计。连胜按 UTC 日期计算，有 Token 或对话记录的日期计为活跃，今天尚未使用时可以接续昨天。最长单轮采用日志明确记录的最大时长，不累加多轮，可能包含等待和暂停。

将指针放到日期格上可查看主要模型、会话、轮次、工具、子智能体、上下文压缩、已记录权限请求和缓存读取占比。主要模型按 Token 排名，会话按日志标识去重；缺少权限事件时显示未知。Codex 已启用原 Hook 统计时继续保留原详情。

底部设备行默认收起，展开后显示各机器在保留期内的已采集 Token。再次打开主面板或切换标签时收起；刷新圆圈在收起时也可点击，标题行除按钮以外的区域都能展开。右侧 `用量详情` 始终直接打开统计窗口。

Claude 额度取启用来源中的最新记录，同一账户的百分比不会相加。读取已有 `~/.claude/ccline/.api_usage_cache.json` 时不运行状态栏程序，也不发起网络请求。该缓存的旧格式只保存七天重置时间，五小时重置时间显示 `--`，不会借用七天时间。已超过明确重置时间的记录显示未知；缺少重置时间时，观察超过对应窗口长度也显示未知。

| 指标 | 来源与边界 |
| --- | --- |
| Token、模型、会话、对话轮次、工具调用 | 日志中实际记录的元数据，包含可读取的子 Agent 日志 |
| 历史额度快照 | Codex 日志中的官方返回值，以及 Claude 官方状态栏被动提供的数字 |
| Claude 等待批准和本轮结束 | 可选 Claude 接入记录的 Hook 事件 |
| 登录方式 | 日志明确提供的身份，或手动指定的来源历史标签；没有依据时为未知 |
| 订阅区间价值 | 本机 ChatGPT 账号的官方 Codex / Work 日统计与已观察周限，提供 Token 折合价值估算 |
| 普通网页 Chat 对话、第三方 API 账单 | 不统计 |

日期统一按 UTC 归档，保留期为 210 天，每次采集清理超期记录。首次扫描会分批继续，来源卡片会提示回填状态。Claude 自身已经清理的日志无法补回，安装前的权限请求历史也不能凭空恢复。

Codex 的输入 Token 已包含缓存读取，推理输出也是输出 Token 的子集，不能再次相加。Claude 的缓存读写与普通输入分开记录，需要单独计入总量。界面中的 Token 不表示订阅账单金额。

相同请求出现在多个文件或机器上时，合计只保留一份完整记录。选择单台机器时显示该机可见记录，因此把各单机视图手工相加可能高于去重后的合计。来源拥有的日志不是严格的物理执行位置证明，复制过会话文件时尤其如此。

## 本机与 SSH

本机和远端需要 Python `3.9` 或更高版本，不需要额外 Python 包。SSH 使用系统 `/usr/bin/ssh`，沿用你的 SSH 密钥、代理跳转和主机配置。

1. 先在终端确认 `ssh dev-a` 可以正常登录，且主机密钥正确
2. 在用量中心添加来源，选择 `SSH`，地址填写 `dev-a`
3. 选择需要采集的工具；例如本机与 `dev-a` 开启 Claude，`dev-b` 只开启 Codex
4. 登录方式不确定或曾经切换过时，保留 `未知`；确认整个来源历史一致时再指定 OAuth/API 标签
5. 在 VPS 安装[定时采集任务](../../Collector/README.md#安装定时任务)，将安装器输出的目录填入来源的 `远端统计缓存目录`
6. 保存后点击 `刷新`

SSH 采用非交互认证，遇到未知或变化的主机密钥会停止，不会自动接受。日志在远端解析，回传请求标识的哈希、计数、日期、模型和项目显示名，原始对话不会下载到 Mac。

默认目录使用 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`，未设置时分别是 `~/.codex`、`~/.claude`。图形界面和 SSH 非交互进程不一定继承终端的环境变量；使用自定义目录时，请在来源设置中明确填写。

推荐模式下，VPS 每 5 分钟自行采集并保存增量索引，Mac 每 5 分钟通过 SSH 只读同步结果。Mac 关闭或离线时，VPS 仍会记录统计。读取失败后逐步延长间隔。

收到系统睡眠通知后，Mac 暂停原 Codex 额度轮询、设备同步、官网分析和额度历史读取，取消排队及在途刷新。macOS 不亮屏的后台唤醒不会自行解除暂停，收到正式工作区唤醒通知后才恢复；Codex 额度会刷新一次，设备同步按原五分钟周期恢复。已发送的请求可能仍收到响应，取消后不会继续发送下一步查询。

这依据系统睡眠状态，不是单纯依据屏幕是否熄灭。外接显示器的正常合盖工作模式若没有进入睡眠，仍按正常周期刷新。VPS 独立定时任务始终按原周期运行。

未填写远端缓存目录时，保留原来的按需模式：每次 Mac 刷新才通过 SSH 启动采集器。两种模式使用相同的数据格式，不需要修改原始日志或重新登录。

## 登录方式

本机和 SSH 刷新会自动读取 Codex 默认登录文件中的类型字段，只回传 `oauth`、`api` 或 `unknown`，不回传凭据内容。当前结果显示在来源设置的 `当前 Codex 凭据` 行，不写入历史统计。项目设置、命令行或环境变量可能覆盖默认凭据，具体历史优先使用会话明确提供的身份。

`历史身份补充` 默认折叠，其中的标签仅补充缺少身份字段的记录。现有标签和旧数据保持原样，不能用当前登录文件倒推过去所有会话。登录切换历史的持久记录及旧记录归类方案仍待确认。

## 订阅区间价值

`全部` 和 `Codex` 的用量中心展示本机 Codex 登录账号的官方分析结果。该卡片固定按账号统计，独立于上方设备日志的机器、模型和日期筛选；API 登录筛选下隐藏。官网数据包括该账号在不同设备上的官方用量。金额以官网为准，历史周限还会从已确认同账号的设备补齐，避免使用全账号金额却只除以单台机器的旧百分比。

认证直接复用本机默认 `CODEX_HOME` 下的 Codex OAuth 登录文件，不读取 Chrome Cookie，不保存或改写登录 Token。官方分析每 15 分钟检查更新，也可以点击卡片右侧刷新。接口失败时保留上一份有效缓存并显示错误，切换账号时隔离缓存。

周期按照真实观察到的七天截止时间切分，提前重置会结束旧行并开始新行。重置附近零用量的短暂截止时间漂移会合并展示。没有历史观察时，不会凭当前截止时间倒推出过去每一周。

在卡片菜单的 `同账号历史周限来源` 中，选择 OAuth 历史属于当前账号的本机和 SSH 设备。选择按账号保存，其他用户默认不启用远端来源。已明确属于 API 或未确认的自定义提供商记录不会进入周限历史，不依赖特定 profile 名称。

若来源当前 OAuth 账号与 Mac 不同，会拒绝该来源的新数据并显示提示。默认凭据为 API、日志缺少历史账号字段时，来源勾选代表你确认该来源的 OAuth 历史属于当前账号，因此不要把不同账号的历史放在同一来源中。日志明确携带账号标识时，还会按账号摘要过滤。

VPS 原定时任务每五分钟增量保存额度元数据，不读取登录凭据或访问 OpenAI。Mac 随官方分析刷新，每十五分钟读取所选设备的额度历史；手动刷新也会触发。尚未初始化、回填未完成或远端缓存过旧时，Mac 使用有界的按需扫描补齐。单台设备失败保留缓存，其他设备继续更新。

同一窗口的百分比不相加，跨设备迟到的旧回执不会覆盖已确认的新进度。截止时间有秒级抖动时用观察时段重叠对齐，实际提前重置仍单独成行。设备证据单独存储，关闭某个远端来源后立即停止使用它的贡献。HTTPS 来源目前保留原 Token 统计，不提供这套历史周限导出。

当前个人账号接口提供日合计 Token 和模型相对额度权重。采用 Quota Compass 的混合单价反推公式估算模型 Token，而不是把额度权重直接当成 Token 比例：

1. 根据当天输入、缓存读取和输出的比例，计算每个模型的混合单价
2. 用模型额度权重除以混合单价，再归一化为模型 Token 占比
3. 分配三类 Token，并按模型价格计算美元和可用费率对应的 credits
4. 用估值时点对应的已消耗周限比例，外推用满周限的金额

外层每行以对齐的日期、已用比例、状态和 `预计周限总额≈…$` 展示，悬浮时高亮提示可展开。展开内容使用浅色圆角虚线卡片，显示当前周期已消费金额及模型明细。

缺少历史数据时，可以在卡片菜单选择周额度参考档位。按用户提供的经验口径 `25 credits = 1 美元`，Pro 5x 的 `12,500–15,000 credits` 对应 `500–600 美元`，Pro 20x 的 `50,000–60,000 credits` 对应 `2,000–2,400 美元`。这不是官方保证的固定周额度。

有完整数据时优先显示用量推算，无法推算时采用所选参考范围，并标注 `额度参考`。不会用参考范围伪造缺失的模型 Token 或历史已用金额。当前档位自动读取官方额度响应，`prolite` 对应 Pro 5x，`pro` 对应 Pro 20x，并按周限周期保存观察结果。升级后收到新响应时，当前周期的档位文案与参考范围自动更新；已记录的历史周期保留原档位。同周期发生档位变化时，不混用两种总额度的百分比外推，改用最后识别档位的参考范围。

菜单里的参考档位只补充没有档位观察的历史周期，按账号保存，默认关闭。应用未观察到的历史订阅变化不会凭当前套餐倒推。

模型 Token、credits 和金额都标为估算，不是官方直接提供的精确账单。Fast 与 Flex 沿用脚本的订阅额度倍率折合美元，不能当作 API Fast 的实际报价；缓存写入与长上下文未单列。价格快照日期显示在卡片底部，来源为 [OpenAI API 定价](https://developers.openai.com/api/docs/pricing)

提前重置当天不会在新旧周期各计算一整天。优先按周限观察中的增量分摊；观察覆盖不足时按时长分摊并明确提示。没有精确日内明细，因此短周期的估算更容易受分摊影响。官方日统计统一使用 UTC，周期起止时间按本机时区显示。

估值与额度比例对齐到同一份官方统计的读取时间，避免用过时 Token 除以更新后的额度比例。最后一天没有使用、末次观察较早，不再阻断外推。没有 Token 且没有额度消耗的空白日不作为缺失数据处理。有额度消耗但 Token 不完整时，按已有样本对应的额度权重比例外推，区间已用金额注明为已记录部分。完全没有可用样本时才采用套餐参考范围。同一周期额度回落时保留参考估算，避免混用不同总额度。每次刷新替换整份官网统计，不累加不同查询的归一化权重。

用量分布默认按模型，四色条显示输入、输出、缓存读取和缓存写入。整行悬浮统一高亮并立即显示一份详细浮层，不必瞄准短色段。额度记录将各工具的最新观察置顶，使用主文字颜色，较早观察变浅灰。每日柱状图支持悬浮查看与点击固定，再次点击同一天取消固定。

展开收起沿用系统窗口动画。设备列表以完整高度固定在原生容器顶部，窗口向下打开时逐行露出；列表不再独立播放高度动画。展开箭头原位即时切换方向，文字不做滑入滑出。收起时内容立即隐藏，避免文字越过已经收缩的卡片边界。

## Claude 被动接入

Claude 的日志统计可以直接使用。已有额度缓存也会自动读取。要补充今后的权限请求、任务状态及官方状态栏字段，在相应来源的设置中选择 `启用补充记录`，确认后完成以下操作：

- 包装现有 `statusLine` 命令，继续向原命令提供完整输入，保留原输出和退出码
- 在原有 Hook 之外追加固定的只读记录回调，不返回批准或拒绝决定
- 将官方提供的额度数字和经过筛选的事件元数据写入本机文件

采集器不读取 Claude 登录凭据、macOS 中的 Claude 凭据或 Claude 认证文件，也不向 Anthropic 发起请求。原状态栏命令原本具有的行为由该命令决定。

官方目前要求 Claude Code `2.1.251` 或更高版本，且满足相应订阅条件并完成首次 API 响应后，状态栏才可能带有 `rate_limits`。这是可选状态栏接入的条件，不影响读取已经存在的 ccline 缓存。缺少字段时保持未知，不根据 Token 数倒推额度。这个字段的可用性说明见 [Claude 官方状态栏文档](https://code.claude.com/docs/en/statusline#rate-limit-usage)

`移除接入` 会恢复原状态栏，并移除本程序添加的 Hook。若状态栏在接入后被你或其他程序修改，卸载会停止并保留现场。该行为用于避免覆盖之后的修改。

也可以在相应机器手动运行：

```bash
python3 CodexBar/Resources/UsageCollector.py install-claude
python3 CodexBar/Resources/UsageCollector.py uninstall-claude
```

如果不愿调整 Claude 配置，保持日志采集即可。账户额度、权限事件和精确等待状态会有所缺失。远程快照与 Claude 状态目前不驱动原有 Codex 通知或防睡眠控制，因为这些被动观察不能替代本机 Codex 的实时读取屏障和生命周期判定。

## 常驻统计端与 HTTPS

需要多个客户端或公网 HTTPS 接入时，可以部署可选的 [Docker 统计端](../../Collector/README.md)。它使用同一采集器与 SQLite，无需额外数据库服务；仅为 Mac 离线时持续统计，使用上述定时任务即可。

- 通过 SSH 访问时，在来源的 `远端统计缓存目录` 中填写宿主机数据目录，例如 `/srv/codexbar/data`，只读取现有数据库
- 通过 HTTPS 访问时，添加 `HTTPS` 来源，填写服务根地址和专用统计令牌；令牌保存在 macOS 钥匙串
- HTTPS 使用系统证书校验并拒绝重定向，不支持关闭证书校验
- 配额快照按来源保留，不把同一账户在两台机器上观察到的百分比相加

## 存储与兼容性

| 位置 | 内容 |
| --- | --- |
| `~/Library/Application Support/CodexBar/UsageCenter/center-v1.sqlite` | Mac 的来源配置、增量游标和经过筛选的统计元数据 |
| `~/.local/state/codexbar-usage/sources/<hash>/usage-v1.sqlite` | 各采集端的文件读取位置和增量统计，遵循 `XDG_STATE_HOME` |
| `~/.claude/codexbar-usage/` | 可选 Claude 包装器、原状态栏配置备份及事件记录 |
| macOS 钥匙串 | HTTPS 统计端专用令牌 |
| `~/Library/Application Support/CodexBar/UsageAnalytics/<account-hash>.json` | 账号隔离的官方统计与周限观察，不含登录 Token |
| 本机采集目录的 `valuation-v1.sqlite` | 旧版本的本机周期证据，保留原格式 |
| 各采集目录的 `quota-history-v1.sqlite` | 新的增量周限证据、可用的账号摘要与套餐元数据 |
| `~/Library/Application Support/CodexBar/UsageQuotaHistory/` | 按账号和来源配置隔离的额度历史缓存 |

用量中心采用独立存储，不修改原 `HookEvents`、`ActivityProtection`、CloudKit schema 或既有设置键。关闭新版后，旧版仍使用原来的数据链路。新统计协议为 `1`，不支持的响应会被拒绝，已有缓存保留。

项目显示名和模型名会跨机器传输。如果它们包含不希望汇总的信息，请暂停对应来源。

## 故障排查

- 显示缓存或采集失败：检查该来源最后更新时间，失败时旧数据会保留
- 显示部分日志无法解析：源格式可能改变，不能把当前统计当成完整账本
- 显示累计计数回退：旧 Codex 日志无法可靠区分回放与计数重置，采集器采用保守方式避免重复累加，可能少计
- SSH 正常但找不到 Python：非交互 SSH 的 `PATH` 与交互式 shell 可能不同，请让 `python3` 在非交互环境可用
- Claude 没有额度：检查被动接入、官方客户端版本和订阅支持，并在官方客户端正常完成一轮任务后刷新
- HTTPS 连接失败：核对域名证书和专用令牌，不能填写 Codex 或 Claude OAuth Token
