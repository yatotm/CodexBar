# 常见问题与排查

简体中文 | [English](../en/UserGuide/troubleshooting.md)

## 菜单栏找不到 CodexBar

- CodexBar 是菜单栏 App，不显示 Dock 图标
- 在 macOS 控制中心设置中确认菜单栏项目没有被隐藏
- 从 Applications 再次启动不会创建第二个实例
- 仍然找不到时，在活动监视器中确认 CodexBar 是否正在运行

## 主面板显示未登录

1. 打开该机器正在使用的 Codex CLI
2. 完成 Codex 登录
3. 双击 CodexBar 主面板中的账户图标刷新
4. 仍然未登录时退出并重新打开 CodexBar

关于页分别列出共享后台的运行版本和 CLI/App 的磁盘版本。来源选项只影响未运行后台的启动，不会切换既有后台的账号或重启任务。

## 主面板显示初始化失败

到 `设置 > 关于` 查看连接错误，确认共享后台实际运行版本不低于 `0.162.0`，再检查 Codex 自身登录、网络与代理配置。修正后点击 `重新建立连接`；持续失败时打开日志查看详情。

## 代理配置或连接失败

先确认同一机器的 Codex CLI 能正常使用。新连接复用官方后台的网络环境，不再读取旧 App 专用代理设置。检查 Codex 自身代理和 `CODEX_HOME`；修正后在关于页重新连接。重新连接仅影响 CodexBar，不会替换正在运行的共享后台。

## 额度或 Token 显示变淡

变淡表示本轮读取失败后回退到了同一账户的缓存数据。

双击账户图标重试；持续变淡时，在关于页面查看连接错误或打开日志。

## 升级后仍有旧 Hook 配置

新版 Codex 采集不再需要 Hook 开关，已有 Hook 历史继续保留。旧配置中的用户和其他 App 回调不要删除。Claude 的 Hook 仍由来源接入管理；出现问题时只检查对应机器的接入状态，不通过切换 Codex Hook 修复。

## 实时任务没有出现

1. 确认本机共享后台已连接，或远端、Claude 来源已接入实时任务
2. 确认 `通用 > 主面板布局` 中的 `任务` 区域已开启
3. 新建一轮 Codex 任务以产生实时事件
4. 本机在关于页重新连接；SSH 来源检查采集器服务和该机共享后台，Claude 则检查其被动 Hook

重新启动 CodexBar 不会补发旧任务通知。

## 收不到系统通知

按以下顺序检查：

1. `系统通知` 总开关是否开启
2. macOS 是否允许 CodexBar 发送通知
3. 对应通知子开关是否开启
4. 对应任务来源是否已接入并有新事件
5. 任务完成时长是否达到所选阈值
6. 通知音效是否选择了静音

触觉反馈不依赖 macOS 通知权限，但依赖 CodexBar 通知总开关。

## 防睡眠没有生效

按以下顺序检查：

1. 随任务模式下，本机 Codex 共享后台是否已连接；手动模式不依赖任务
2. `防止系统睡眠` 是否开启
3. 随任务模式下，是否有符合条件的本机 Codex 任务
4. 只有等待任务时，`等待批准时保持防睡眠` 是否开启
5. 设置页是否提示需要批准 CodexBar 后台运行
6. 是否正在触发低电量保护
7. 是否已经达到最长防睡眠时间

防睡眠标记表示系统睡眠当前确实被阻止，开关打开但没有防睡眠标记不一定是故障。

如果设置页显示 `系统睡眠已由其他来源关闭`，CodexBar 不会覆盖该来源。

## CodexBarHelper 无法注册

- 确认 `自动重置` 或 `防止系统睡眠` 已开启；关闭状态不显示 Helper 状态说明
- Helper 等待系统批准时，点击设置行下方的 `打开系统设置` 并允许 CodexBar 后台运行
- 确认 CodexBar 位于 Applications 中且 App 包完整
- 如果提示服务异常或 CodexBarHelper 文件缺失，重新安装完整 CodexBar App
- 更新后持续失败时退出 CodexBar，重新打开并再次检查授权

## 自动重置没有按时执行

按以下顺序检查：

1. `自动重置` 是否开启，提前量是否符合预期
2. 自动重置设置行是否提示 CodexBarHelper 待批准、未注册或唤醒计划失败；临期选项按钮只在 Helper 已获得系统批准时显示
3. 主面板是否显示可用留存重置及其过期时间
4. 计划时间到达后，网络与 Codex 登录状态是否可用
5. “自动重置通知”是否开启；通知关闭不会阻止自动重置本身执行

暂时故障每轮最多连续重试 5 分钟，后续刷新仍可再次尝试。关闭自动重置或退出 CodexBar 会取消唤醒计划。

## 更新 Codex 后仍显示旧版本

关于页的 CLI/App 行显示磁盘版本，共享后台行显示实际运行版本。升级安装文件不会立即替换已经启动的后台；CodexBar 的 `重新建立连接` 也只重连客户端。结束当前任务并按 Codex 自身方式更新或重启后台后，再连接即可读取新版本。

## 使用日志窗口

打开方式如下：

- 右键菜单栏图标并选择 `日志`
- 主面板打开时按 `⌘L`

日志窗口保留本次运行期间最近 500 条 Codex 交互记录。

每条记录包含请求时间、方法、状态和响应时间，展开后可以查看请求、响应或错误预览。

全文格式化和排版在后台完成，浏览旧记录时新日志不会强制拉回顶部。完整内容可预览或复制，清空或退出 App 后不会恢复。

## 反馈问题

提交问题时说明复现步骤、CodexBar 与 Codex 版本、可见错误。交互日志可能包含账户和请求内容，分享前请检查隐私信息。

## Claude 额度未记录

先确认是订阅登录，再确认客户端缓存是否包含 5h/7d 数据。软件会取已配置同账号设备的最新可用记录，不主动联网补齐；旧缓存可能没有五小时重置时间。API 模式和缺失字段显示未记录属于正常降级。

## VPS 或热力图未更新

检查 SSH 别名能否无交互连接、来源是否启用，以及远端缓存目录是否与安装器输出一致。使用定时采集时确认 `codexbar-usage.timer` 处于 active；一次采集结束后 service 显示 inactive 是正常状态。Mac 睡眠期间停止同步，VPS 可继续采集，恢复后再补齐。

## 价值估算与本机 Token 不一致

官网分析覆盖当前账号，日志统计覆盖已接入设备，两者不是同一个范围。先检查同账号历史来源和 OAuth/API 分类，再查看周期展开后的估算依据、重置边界和缺失提示。不要把缓存读取、credits、额度百分比和美元当作同一种计量。

## 无法检查 fork 更新

Debug 构建不走正式更新通道；从上游首次切换需要手动安装。正式版只读取本仓库发布的更新，不跟随上游 tag。签名和迁移要求见 [切换到独立 fork](migration.md)

## 未公证安装包首次打开

当前 Release 提供通用 DMG，将 `CodexBar.app` 拖入 Applications 后打开即可。若系统阻止首次启动，到 `系统设置 > 隐私与安全性` 选择 `仍要打开` 并确认。无需关闭系统的整体安全保护。操作位置见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)

本版使用开发签名，防睡眠和自动重置需在首次开启时确认，并按提示允许 CodexBar 后台运行。自行构建的临时签名包没有可验证的 Team ID，这两项功能仍不可用。iCloud 已移除，统计、官网分析、SSH/HTTPS 与 Sparkle 更新不依赖电源权限。
